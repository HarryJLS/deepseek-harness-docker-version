# 配置与状态拓扑

容器将启动信息、可变配置和持久数据分别交给不同的所有者。[部署参考](README.zh.md) 定义完整字段和访问要求，[配置教程](CONFIGURATION-GUIDE.zh.md) 提供操作步骤。

| 类别 | 所有者 | 内容 | 生效方式 |
|---|---|---|---|
| 启动信息 | 镜像及部署环境 | Nacos 坐标、监听端口、提供方选择 | 启动或重建镜像 |
| 配置信息 | Nacos | 数据库连接、应用名、模型设置、凭据、插件清单和补丁 | 数据库、应用名与安装清单需重启；其他配置按其声明更新 |
| 运行数据 | OceanBase MySQL 模式 | 会话、事件、共享 KV 与图片 | 事务提交后持久化 |

## 启动顺序

入口程序先连接 Nacos，读取并校验数据库配置，然后准备配置档、安装清单中的插件，最后通过 dsh 启动 Web 配置档。数据库选项不回退到运维环境变量，缺失或无效的条目会阻止应用启动。

Nacos 自己的地址必须在连接前可用，因此保留为启动输入。Nacos 开发账号密码集中在 [deployment-config.mjs](deployment-config.mjs) 的 `NACOS_AUTH` 中；生产密钥不得提交到仓库。数据库地址、账号和连接池选项由 Nacos 管理，不能混同于 Nacos 的启动坐标。

## 应用与用户归属

应用通过 Nacos 命名空间分开配置，通过数据库的 `app` 列分开行。应用名原样存储，不转换为 schema 名。会话和附件的 `user_id` 区分用户，缺失用户信息时使用 `-`。所有 OceanBase 表使用独立的雪花主键和统一审计字段，逻辑标识另设唯一索引。

HTTP 与 WebSocket 使用相同的可信用户请求头。平台必须认证用户并替换外部传入的身份信息；会话隔离不等于文件系统、shell 或全局设置的租户沙箱。[用户隔离要求](README.zh.md#user-isolation) 定义具体责任。

## 数据库与缓存

[schema-mysql.sql](schema-mysql.sql) 是表结构的唯一手工部署参考。应用可以跳过已经预建的表所需的 DDL，但会拒绝缺少审计字段或雪花主键的既有结构。变更格式前必须备份并由运维转换数据，不会自动修改旧表。

模型请求的派生图片变体与搜索索引是可重建缓存，可以留在容器本地；原始会话事件和归一化图片存放在 OceanBase。活跃 Agent 和任务属于各自进程，数据库共享不提供分布式执行所有权。
