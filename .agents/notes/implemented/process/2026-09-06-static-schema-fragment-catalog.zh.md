# Agent Note: 配置目录中的静态共享字段

Status: implemented

[English](2026-09-06-static-schema-fragment-catalog.md) | 中文

## 问题

OceanBase 和 Nacos 提供方通过对象展开共享连接字段。拒绝这些声明的配置目录无法重新生成，而跳过这些字段的目录无法发现插件接收但配置类型未声明的字段。

## 决策

[配置目录生成器](../../../../scripts/gen-config-catalog.ts) 通过本地或工作区的具名导入及包内重新导出来展开常量对象字面量。生成器只读取源码，不执行插件模块。在按照配置类型检查嵌套路径之前，后面的属性会替换前面展开的同名值。

无法解析或动态生成的展开、循环引用和非普通属性键都会导致检查失败。检查枚举字段路径，不计算运行时默认值。它不替代 Schemastery 校验，也不替代[工具目录的运行时模式收集](2026-07-02-tool-schema-catalog.zh.md)。

## 考虑过的替代方案

**跳过共享字段。** 提供方可能接受未记录的连接字段，而检查仍然报告成功。

**在每个提供方中重复字段。** 重复声明会让不同提供方的可接受字段、默认值和秘密字段标记逐渐不一致。

**执行包初始化代码。** 即使字段名称可以静态获取，文档生成仍会承受模块副作用和依赖要求。

## 影响

生成的目录包含已部署的 Nacos 和 OceanBase 提供方，无须修改其运行时配置。不支持的动态字段构造仍会明确报错。

[生成器专项测试](../../../../packages/examples/agent-spine-demo/tests/gen-config-catalog.spec.ts) 覆盖共享导入、重新导出、嵌套数组、属性优先级，以及对隐藏、动态或循环字段的拒绝。已有工具目录决策继续有效，因为它负责运行时组合的模型模式，而不是静态配置声明。
