# Agent Note: Redis 会话上下文与临时附件引用

Status: implemented

[English](2026-09-12-redis-session-context-and-temporary-attachments.md) | 中文

## 问题

部署副本需要共享上下文缓存，同时不能把整段对话或一个用户的所有会话放进持续膨胀的 Redis 值中。临时截图不应占用数据库或 Redis 容量，删除文件也不能悄悄改变从会话日志重建的模型历史。

## 决策

MySQL 提供方在 SQL 事务成功后将已提交事件缓存到 Redis。读取先通过数据库会话头校验归属，并获取固定日志范围，再使用缓存事件页。缺失、损坏、过期或部分淘汰的页从 MySQL 读取并回填。运行时 Redis 故障不影响已持久化写入；配置的 Redis 无法连接时启动失败。

SQL 序列化保留 JSON 字符串值与键，包括指令标识中使用的 NUL。持久化时替换控制字符会使 Redis 热读取不同于数据库冷读取，因此两个存储保留相同的逻辑事件值。

key 以 `dsh-` 开头，包含应用、数据库、用户、会话和物理行标识。每个事件有独立的带校验和值，较大值采用有界字节分块，所有 key 均过期。Nacos 管理连接、TLS、凭据、单值限制、流水线大小、超时和默认两天 TTL。不创建整段会话的 Redis 列表、全局用户文档或二进制附件值。超过缓存限制的事件完整保留在 MySQL 中。

Docker 部署包选择本地附件提供方的显式临时模式。文件位于配置的相对目录下，并按用户隔离。会话引用包含路径、文件名和已验证的元数据。Agent 执行下一步前，缺失文件转换为纯路径内容；已有模型历史通过普通的带来源表面替换修改，并记录在会话日志中。此部署之外仍默认使用持久化本地附件。

[用户归属决策](2026-09-06-oceanbase-user-ownership.zh.md) 继续负责请求身份与 SQL 审计字段。[持久图片决策](../feature/2026-07-22-web-multimodal-image-input-and-durable-attachments.zh.md) 继续负责普通图片准入和持久化默认值；临时部署保留策略是显式例外，不是隐式削弱默认保证。

## 考虑的替代方案

**每段对话一个 Redis JSON 值。** 长日志会产生大值，每次更新也会重写完整前缀。独立的有界事件值保留增量发布，并支持部分缓存恢复。

**将 Redis 作为持久化权威或授权来源。** 淘汰、故障、旧 key 和行重建不能授予访问权或丢失已提交历史。数据库归属与日志范围仍具有权威性。

**仅在缓存序列化时移除图片载荷。** 这会使 Redis 历史不同于已提交日志和活跃模型历史。附件准入已分离字节；文件消失通过记录替换表示。

**将临时图片原件存入 MySQL。** 这违背部署的文件保留策略。所选提供方写入临时文件，日志中仅保留引用。

## 影响

Redis 保存可重建上下文，不管理活跃 Agent 归属。活跃 Agent、收件箱、任务和事件流仍属于各自进程，因此跨节点恢复执行前需要网关会话亲和与停止原执行节点。SQL 锁拒绝重叠事件序号，但不是分布式执行租约。冷恢复仍在执行进程中分配完整逻辑会话。

临时图片预览可能不可用，已开始的请求也可能因并发清理文件而失败。Redis TTL 不删除 SQL 历史或清理文件。Redis 策略与连接变更在进程重启后生效。已有 SQL 附件行保持不变。

## 测试

定向测试覆盖缓存校验和、UTF-8 分块限制、流水线边界、逐 key TTL、身份隔离、损坏及缺失分块、取消与连接故障。临时文件测试覆盖相对路径校验、用户隔离、已记录替换、嵌套工具图片、重放和监听器释放。免密钥的 `temporary-image-expiry` 场景启动随附 headless 配置档，并在已记录图片文件删除后继续执行。Redis/MySQL 集成测试使用独立连接，覆盖热读取、过期回填、并发追加拒绝、软删除以及仅留数据库的超大事件。
