# Agent Note: OceanBase 与 Redis 使用共享 Session 格式目录

Status: implemented

[English](2026-09-15-oceanbase-redis-stable-format-adapter.md) | 中文

## 问题

OceanBase 提供方将 Session 头和事件保存为 JSON，Redis 保存可丢弃的事件副本。如果任一提供方直接把这些值强转为当前 TypeScript 类型，每次 Session 格式发布都需要修改提供方代码，旧 Redis 项也可能被误当作当前事件。

## 决策

OceanBase 对每次数据库读写都使用构建时固定的 `dsh-session-format-catalog`。受支持历史代际的数据库行先通过完整的相邻迁移链解码和迁移，再由提供方返回逻辑 Session。新行使用目录的当前编码器。历史 Session 在下一次追加前于同一事务中改写为当前物理格式；只读恢复不会修改数据库。未来代际或格式损坏会在解释消息字段前被拒绝。

Redis 只缓存当前逻辑事件。缓存 key 身份哈希和缓存包都带有已安装的 Session 格式版本，因此早期代际的缓存项会变成 miss，不会成为当前 Session 代码的输入，同时保留既有 key 前缀。OceanBase 继续作为归属、事件范围和历史恢复的权威；Redis 不执行格式迁移，也不执行授权。

因此，提供方依赖稳定的目录 API，而不是在存储逻辑中命名 V0、V1、V2 或 V3 消息字段。未来格式发布只需更新目录和迁移链；除非存储策略本身变化，OceanBase 与 Redis 提供方代码不需要跟随修改。

## 考虑过的替代方案

**把数据库 JSON 直接强转为 `SessionEvent`。** 代码较短，但会绕过历史转换，使物理编码细节泄漏到每次存储读取，并可能静默返回错误消息。

**让 Redis 缓存数据库的每种物理表示。** 缓存项可能比写入它的代际存活更久，也无法安全地迁移不完整的分页结果。带版本的当前逻辑事件可以让旧值直接丢弃，再从 OceanBase 恢复。

**启动时重写所有历史 Session。** 启动会变成无界的数据迁移，一个无关的旧行也可能阻塞部署。下一次写入时惰性重写可以保留读可用性并服从现有事务归属。

## 后果

数据库行不是当前格式时，历史读取会先生成完整的逻辑事件列表，因为相邻迁移阶段可能展开或重新编号事件。当前格式缓存 miss 也使用同一个目录解码，再发布逻辑分页结果。旧 Redis key 会被带版本的 key 身份哈希有意放弃，并按照原有 TTL 过期；可见的 key 前缀保持不变。

聚焦适配器测试覆盖 V0 恢复、当前格式往返、未来版本拒绝以及跨代 Redis 缓存 miss。OceanBase 集成测试继续作为事务级重写行为的权威验证。
