# Agent Note: OceanBase 审计行与请求用户归属

Status: implemented

[English](2026-09-06-oceanbase-user-ownership.md) | 中文

## 问题

共享平台必须将会话归属、应用身份与数据库行标识分开。仅过滤侧栏仍会让直接读取、显式 ID 接管、缓存观察、附件和实时通知暴露其他用户的会话。数据库凭据同时来自部署环境与远程设置，还可能让缺失的配置连接到非预期数据库。

## 决策

每张 OceanBase 表都有有符号 BIGINT 雪花 `id` 和五个必需审计字段。逻辑标识保留唯一索引；会话的既有标识是 `session_id`，不是数字主键。标识采用二进制比较。一个进程按配置的工作节点编号共享生成器，在时钟回退时保持时间单调，并在序列耗尽时推进逻辑毫秒。共用表的副本必须使用不同工作节点编号并同步时钟。

Connection 按配置的用户请求头为已由网关认证的请求设置作用域，缺失信息时使用 `-`。会话头持久化 `userId`；分叉与委派子会话继承该值。会话读取方在活跃与冷观察上校验归属，流则捕获准入时的用户。MySQL 会话与附件查询包含所有者；共享 KV 单元仍归应用所有。更新保留创建来源和行 ID，KV 删除将行标记为已删除，再次写入会恢复该行。

容器在准备配置档之前从 Nacos 读取并校验全部数据库连接字段。缺失配置会停止启动。启动程序通过名称带 secret 的内部环境变量以及 `/run` 下权限为 0600 的文件传递已校验文档；两者都不是面向运维的配置回退。源码中的 Nacos 凭据是本地开发示例，不是生产密钥。不兼容的既有表结构会被拒绝；数据转换必须由运维基于备份显式执行，不属于运行时兼容路径。

## 考虑过的替代方案

**仅过滤列表。** 如果所属读取方和写入方不执行限制，直接会话地址、搜索结果、缓存准备对象和共享事件流仍可访问。

**用雪花 ID 替换对话标识。** 对话标识出现在持久化事件和两个 SDK 中。独立数字行主键满足数据库要求，同时避免混淆物理行与逻辑会话。

**数据库设置回退到环境变量。** Nacos 条目不可用或不完整时可能静默选择其他存储介质。启动时强制校验要求运维先解决配置缺失，再让服务就绪。

## 后果

会话归属保护平台会话 API，不保护文件系统、shell、全局设置或管理员插件。网关必须替换 HTTP 与 WebSocket 流量中的用户请求头，并阻止公网直接访问 harness 端口。无用户作用域的 Host 维护操作保留访问所有用户的能力，该作用域不能由调用方选择。匿名请求有意共享 `-` 所有者的会话。

聚焦测试覆盖并发用户作用域、活跃与冷会话拒绝、流过滤、无效 Nacos 字段、shell 安全的密钥传递、雪花序列耗尽，以及 OceanBase 审计写入、归属校验、软删除和事务回滚。JSONL 会话头与 SQLite schema 20 保留同样的可选归属元数据，不兼容的 SQLite 结构会被拒绝。
