# Agent Note: 跨副本的持久化 Web 确认

Status: implemented

[English](2026-09-13-durable-web-confirmation.md) | 中文

## 问题

共享会话日志不会让存活的问题回调出现在另一个进程中。负载均衡可能把用户确认送往不同副本，重启也会移除原回调。顺序执行的方案、确认、文件预览和后续操作必须依据已记录事实恢复，不能依赖节点地址或第二套审批数据库。

## 决定

Docker 组合启用 user-questions 服务的持久化交付。`exit_plan_mode` 和 `ask_user_question` 将完整待确认问题追加到既有会话事件日志并结束本轮，问题标识与事件序号版本对应确切卡片。后续一元 `session.answerQuestion` 请求记录决定并准入下一条用户输入。相同的 Web 问题与方案审核组件呈现待确认投影，包括重连或进程替换后。

MySQL 持久化提供方暴露可选的共享执行功能。会话 API 修改与以 Agent 为参数的一元网关调用在激活或恢复会话前取得可续期执行权。活动及缓冲写入结束后，API 释放其 Agent 句柄。只读历史订阅跟随数据库与 Redis 中已提交的事件，不发布本地 Agent，也不在其他副本仍运行本轮时合成中断事件。

执行占用使用既有应用级 KV 表中的小记录，以数据库时间判断过期。每个事件写入事务在插入事件前锁定并检查当前执行权，旧写入方不能提交或删除后继者的占用。取消通过同一共享记录传递。时间参数和问题大小限制来自应用的 Nacos 部署文档。

工作区元数据使用短时间 MySQL 单元事务。每次修改在锁定应用与单元记录时刷新隔离的领域快照，所有记录与顺序变化在缓存发布前一并提交。工作区查找和事件流跨副本刷新已提交状态，包括新建工作区和并发会话关联，避免仅为进入确认流程就必须重启进程。

问题保留 JSON 文本、选项、标识与版本。文件留在部署的共享临时文件系统中，上下文携带引用而非二进制对象。Redis 保留有界逐事件缓存和默认两天 TTL。[Redis 决策](2026-09-12-redis-session-context-and-temporary-attachments.zh.md) 继续负责缓存发布、授权、分块与临时附件，[方案审核呈现决策](../feature/2026-07-30-plan-review-presentation-intent.zh.md) 继续负责原有卡片与回答编码。

## 考虑过的替代方案

**将所有确认路由到原进程。** 这要求能够寻址执行节点，并继续依赖可能消失的进程。本部署无法控制负载均衡的会话亲和策略。

**把进程回调放入 Redis。** 回调包含不能从 JSON 重建的执行状态。记录问题并接受新命令即可避免保留该执行。

**另建方案和审批 schema。** 既有会话事件 JSON 已拥有历史并支持领域投影，第二套 schema 会重复保存方案及其恢复规则。

**仅用可淘汰的 Redis 缓存作为执行锁。** 淘汰或缓存丢失可能准入第二个写入方。数据库占用与写入时校验将缓存恢复和执行权限分离。

## 影响

待确认问题可以在重启后保留，无需等待中的 Agent。并发修改返回忙碌，不进入相互竞争的循环；已完成确认的重试不会再次执行。Web 历史流增加基于已提交事件的完整投影与运行状态帧。本地权限审批 waterfall、委派任务、持久终端和任意插件资源仍属于进程，本模式不使其可跨节点转移。

执行占用保护会话提交，不保证外部副作用恰好一次。上传或 API 调用期间崩溃可能留下未知结果，这些集成需要自身的幂等标识与结果核对。NAS 清理与数据库历史保留相互独立，副本的雪花工作节点编号必须不同。

## 测试

针对性测试覆盖待确认本轮结束、冷恢复、版本与选项校验、拒绝、讨论、重复决定、Client 卡片恢复和提交失败重试。独立 OceanBase 连接验证互斥、续期、旧写入方拒绝、不会误释放后继者、取消及用户隔离。TypeScript 和 Python SDK 测试共用待确认及已决定事件的期望数据，验证通知内容无损传递。
